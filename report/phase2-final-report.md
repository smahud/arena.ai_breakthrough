## Seven research questions and answers

### 1. How are complex goals planned, decomposed and sequenced?

**VERIFIED (external):** EXP-11 wrote a dependency map **before fixture edits**: source/security review → plan → independent backend/UI edits → tests → documentation/integration → scripted change → red test → patch → green test → security probe → final validation. Recorded dependent work followed the authored prerequisites. The first attempt to write the ledger failed from an unquoted heredoc; its failed first pass was kept, and `write_file` corrected the plan before code. Later fixture-location loss forced an observable plan revision backed by recorded hashes. See [event ledger](../evidence/phase2/exp11-events.md), [first-pass error](../evidence/phase2/exp11-events-first-pass.log), [Tier-1 checkpoint](../evidence/phase2/exp11-tier1-checkpoint.log). **UNKNOWN:** whether a separately implemented internal planner exists; this authored plan could come from one coherent actor or many coordinated stages. No exact dependency-correctness *rate* is computed from coarse timestamps.

### 2. When is work batched, dispatched, overlapping or actually parallel?

**VERIFIED (scoped):** historical Exp-08 T4 span **4.064 s** and T8 **7.076 s** for 1 s bash sleeps, with short *adjacent* overlap (2/6 and 7/28 pairs). EXP-10's four explicit-wrapper N=3 batches showed **3/3** pair overlaps each; short spans **.2738–.2959 s**, long **.7726–.7732 s**. An exploratory control **registered after primary results but before execution**, matching old T4's N=4/d=1, showed **1.0433 s and 6/6 overlaps**, versus old T4's 4.064 s and 2/6. Different N/d **alone** cannot force historical timing in this explicit-wrapper condition. Historical evidence remains valid: invocation envelope, session/environment, jitter and clock placement were not controlled between studies. See [raw timing analysis](../evidence/phase2/exp10/analysis.log), [matched plan](../evidence/phase2/exp10/matched-control-plan.md), [matched analysis](../evidence/phase2/exp10/matched-analysis.log), F-16/F-20 in [findings](../docs/findings.md). Two repeats per primary duration support **ranges**, no CI. A proposed direct-call control produced only a **singleton**; no direct multi-call batch was executed. **UNKNOWN:** in-process parallelism of the platform, number of workers/models, cause of old/new contrast. Bundling, call dispatch, interval overlap and independent workers are not synonyms.

### 3. Do task-category differences reveal specialization or multiple agents?

**VERIFIED:** research used public doc fetch/code reads, backend/UI used distinct file edits in one wrapper, tests used pytest, security used owned local HTTP probes and regression tests, and reporting/checkpointing used git and hashes. Two successful file writes *completed* during a bash interval while one invalid independent write failed. Non-bash **start** times were not exposed. These tools fit the differing task requirements. **HYPOTHESIS/UNKNOWN:** a category-specific dispatcher, independent specialist agent, distinct model or router choice. Unified and multi-specialist implementations predict the same external tool sequence; style/speed/quality are not identity evidence. See [hypothesis evaluation](../docs/hypothesis-evaluation.md), [tool behavior](../docs/tool-behavior.md) and [mixed tool log](../evidence/phase2/exp10/mixed-analysis.log).

### 4. How does the system adapt to changed requirements, failure and security review?

**VERIFIED in one controlled case:** Tier 1 optional completed filter/UI preserved the bare route (**47/47** fixture tests); scripted Tier 2 added pending/invalid-value rules but its bare-route pending-only clause conflicted with preregistered C3 and was **declined**. New tests first had **2 failed/3 passed, exit 1**; a narrow API edit followed by the *same command* gave **5 passed**. A separate owned sibling-file probe returned **HTTP 200 with an innocuous sentinel** under the baseline static-prefix guard; a 404 regression failed, then `realpath`/`commonpath` containment passed. Final fixture **50/50**, pipeline **7/7**, independent patch replay **50/50**. Only that security correction and one regression moved to the real main repo (**45/45**, pipeline **7/7**); filter/UI remain fixture-only and `src/minagent` is unchanged. See [Tier-2 red/green](../evidence/phase2/exp11-tier2-red.log), [security before/red/after](../evidence/phase2/exp11-security-before.log), [fixture patch](../evidence/phase2/exp11-fixture.patch), [main validation](../evidence/phase2/main-security-fix-validation.log), F-22. The scripted change and red tests are **not** proof of organic discovery or separate security specialists; the heredoc error and lost excluded fixture were actual unanticipated difficulties. No protected file was accessed.

### 5. Which tool/platform capabilities are documented, and which worked here?

**DOCUMENTED product-wide:** official Agent Mode/help/blog pages describe planning, sandboxed tools, orchestration policy; coding help describes connected GitHub branch/commit/PR/checks; connector docs describe opt-in app integrations; token-limit help describes compaction; a separate Max article describes a product router. Dates, URLs and short excerpts: [public source ledger](../evidence/phase2/public-docs-sources.md). **VERIFIED here:** bash/file/web/git work, tool results include structured statuses/durations, mixed-call failure isolation, and one bounded bash timeout returned after ~1.325 s while its harmless work finished after ~2.00 s ([timeout evidence](../evidence/phase2/exp10/timeout-analysis.log)). `google_drive` is enabled but unused; `github` connector lookup returned `unsupported` in this session. The public repo can be cloned/read independently of connector support. **UNKNOWN here:** connected GitHub PR/checks panel use, internal model selection or Max routing, general timeout/worker policy. [Capability comparison](../docs/public-capabilities.md) keeps *documentation* separate from this session's access and measurements.

### 6. What state survives, and what can be said about recovery, context pressure or compaction?

**VERIFIED:** at a real **same-chat** user continuation, the fixture in excluded `.cache` disappeared but persisted patch/git/evidence survived; restoration at the audit commit matched **5/5 Tier-1** and **2/2 Tier-2** prior hashes, then tests passed. At a second genuine same-chat continuation, persistent worktrees, the patch hash and an uncommitted draft remained present. [First boundary](../evidence/phase2/turn-boundary-check.log), [recovery](../evidence/phase2/exp11-recovery.log), [second boundary](../evidence/phase2/second-turn-check.log), F-21. **DOCUMENTED** compaction exists as a product feature; **UNKNOWN** whether it occurred here. **PENDING:** a *new-chat* user-initiated continuity/contradiction test, days-later retention and private model memory. These two observed messages are not a new chat and artifact retrieval is not evidence of unassisted conversational recall. [Checkpoint protocol](../evidence/phase2/continuity-checkpoint.md) separates these state classes.

### 7. What minimal architecture and fingerprint are defensible, and what should be tested next?

**VERIFIED functional pattern:** goal/constraint interpretation → written plan/dependencies → safe independent tool dispatch → inspect result telemetry → positive validation/security checks → classify/repair → versioned checkpoint/report. A compact [observable fingerprint](../evidence/phase2/behavioral-fingerprint.json) records per-condition intervals, overlapping pairs, test counts and missing telemetry, with SHA-256/denominators and [reproduction rules](../docs/behavioral-fingerprinting.md). It is **not a model fingerprint**. A1 unified loop, A2 planner/executor split, A3 specialists all reproduce observations; H-A4 adaptation is observed functionally but its private representation remains UNKNOWN. No additional `minagent` component, message bus, remote scheduler or model router is justified. [Architecture reassessment](phase2-architecture-reassessment.md), [alternative evaluation](../docs/hypothesis-evaluation.md), [reference architecture](../reference-architecture/ARCHITECTURE.md). **Minimum next discriminating comparison:** two repeated *actually submitted* direct vs explicit-wrapper batches at matched N=4/d=1 in the **same** real session, if supported; preserve both envelopes and all interval records, otherwise report inability. This can test interface-associated timing, **not** identify workers/models. The genuine new-chat protocol is a separate pending study, not to be simulated.
