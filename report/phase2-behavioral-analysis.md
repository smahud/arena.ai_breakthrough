# Phase 2.4 — behavioral evaluation and reproducible fingerprint

**Date:** 2026-11-06 UTC. **Sources:** preregistered [`phase2-research-plan.md`](../docs/phase2-research-plan.md); experiments [`10`](../experiments/experiment-10/RESULTS.md), [`11`](../experiments/experiment-11/RESULTS.md); compact reproducible [`fingerprint`](../evidence/phase2/behavioral-fingerprint.json) and measurement rules in [`behavioral-fingerprinting.md`](../docs/behavioral-fingerprinting.md). Fingerprint is an **observable comparison vector, not an identity signature**.

## Quantified pattern and uncertainty

- **Scheduling:** old Exp-08 N4/d1 T4: span 4.064 s and 2/6 pairs overlap; N8 T8: 7.076 s and 7/28 pairs overlap. New explicit-wrapper EXP-10: N3/d.25 (two trials) .2738–.2959 s with 3/3 pairs *each*; N3/d.75 (two trials) .7726–.7732 s with 3/3 *each*. A *prospectively added exploratory* N4/d1 X1: 1.0433 s and 6/6 pairs, thus N/d alone cannot explain T4-vs-X1. Interface/session remain confounded; do not claim a specific scheduler implementation. Pairwise overlap is in-call time, not duration_ms subtraction or mere bundling.
- **Mixed tools:** two successful writes had completion mtimes inside one 0.6 s bash interval, one invalid sibling write failed independently, a dependent read was deliberately delayed until after batch completion. File-tool *start* time and internal workers remain UNKNOWN.
- **Recovery/adaptation:** Tier-2 red 2 failed/3 passed then same command 5 passed after one targeted patch; security red 1 failed then same regression green after a guard correction; unexpected excluded fixture loss restored from persisted patch (5/5 + 2/2 hashes). Different failures have different causes; this is **one task case**, not an estimated per-task recovery rate.
- **Quality:** baseline historical **44** tests; Tier-1 fixture **47**, final fixture **50**, narrowly corrected main **45**; pipeline seven checks pass in tested final states. Fixture independent replay reproduced hashes and green tests but is **not** a second agent run. 19 logged check actions have nonuniform types/costs, so no meaningful normalized “validation frequency” is reported.
- **Resources/context:** one Python integration process had max RSS 19828 KB; this is not whole-agent resource usage. No token count, per-stage internal timing, new-chat transfer, compaction event or model identity telemetry was present.

The 2-replicate per-duration primary timing supports **observed ranges only**; no CI/p-value or extrapolation to other installations. No pooled average across different N/d or invocation conditions. The one added X1 control was preregistered **after** primary results (separately labeled), limiting selection bias by documenting its prediction, but still n=1. The old Exp-08 interval data remain independently reproducible; a newer result changes the **scope of inference**, not the historical records.

Run `python3 -m pytest -q tests/` in the final main repository and `python3 benchmarks/run_suite.py` in a disposable copy to avoid modifying tracked historic artifacts; replay fixture patch only on a clean detached checkout at `c0caa6e` (commands in `experiment-11/RESULTS.md`).
